Build a polished, highly interactive mobile prototype called "BharatQuest" for Smart India Hackathon 2026 Problem Statement SIH26208.

IMPORTANT: Do not create a generic educational app. This must feel like a real adventure/game product whose GAME WORLD is India's civilization, history and culture.

==================================================
1. PRODUCT
==================================================

APP NAME:
BharatQuest

TAGLINE:
"Play. Explore. Discover India's Heritage."

PROBLEM STATEMENT:
SIH26208 — Student Innovation-Challenge: conceptualize and develop unique toys and games based on our civilization, history and culture.

CORE IDEA:
BharatQuest transforms India's heritage into an interactive exploration game.

The player:
EXPLORES → DISCOVERS → PLAYS → EARNS XP → COLLECTS → UNLOCKS

The prototype should demonstrate how historical and cultural knowledge can become the actual game environment.

3. AUTHORITATIVE DATA REQUIREMENT
==================================================

THIS IS VERY IMPORTANT:

Do NOT invent historical facts, dates, UNESCO status, coordinates, descriptions or heritage classifications.

Every factual heritage item displayed in the application must have a "Source" field.

PRIMARY SOURCE:
UNESCO World Heritage DataHub:
https://data.unesco.org/explore/dataset/whc001/

Dataset:
whc001 — World Heritage List

UNESCO API documentation:
https://data.unesco.org/api-console/explore/v2.1/

UNESCO API dataset endpoint pattern:
https://data.unesco.org/api/explore/v2.1/catalog/datasets/whc001/records/

Use fields such as:
- name_en
- short_description_en
- description_en where available
- date_inscribed
- category
- cultural_criteria
- criteria_txt
- states_names
- coordinates
- main_image_url
- main_image_author
- main_image_copyright
- main_image_caption_en
- components_list

Filter the UNESCO dataset to India using the appropriate country/state field rather than manually inventing a list.

SOURCE ATTRIBUTION:
Every UNESCO-derived heritage detail should display:
"Source: UNESCO World Heritage DataHub"

And provide a "View Source" button linking to:
https://data.unesco.org/explore/dataset/whc001/

SECONDARY OFFICIAL SOURCE:
Government of India's Open Government Data Platform:
https://data.gov.in/

Use it for Indian government datasets when relevant, especially datasets published by:
- Ministry of Culture
- Archaeological Survey of India (ASI)
- Ministry of Tourism

Relevant official ASI/government dataset examples:
https://www.data.gov.in/

Search/use official ASI protected-monument datasets from the data.gov.in catalog rather than creating unsupported monument lists.

For government-derived information display:
"Source: Government of India — data.gov.in"

SOURCE PRIORITY:
1. UNESCO / official international heritage source
2. Government of India / ASI / Ministry of Culture
3. Only if neither source provides a required field, leave that field unavailable rather than inventing it.

Never silently replace missing authoritative information with AI-generated facts.

4. DATA ARCHITECTURE
==================================================

Create a backend service.

Backend responsibilities:

GET /api/heritage
GET /api/heritage/:id
GET /api/heritage/india
GET /api/heritage/search?q=
GET /api/heritage/region/:region

The backend should fetch UNESCO data server-side rather than exposing API credentials in the mobile application.

Create a normalization layer:

UNESCO API
      ↓
Backend Fetcher
      ↓
Data Validation
      ↓
Normalized Heritage Object
      ↓
Database Cache
      ↓
React Native App

Normalized object:

{
  id,
  name,
  description,
  shortDescription,
  country,
  state,
  latitude,
  longitude,
  category,
  yearInscribed,
  criteria,
  imageUrl,
  imageAuthor,
  imageCopyright,
  sourceName,
  sourceUrl,
  sourceType
}

Do not store fabricated values.
